# 《基于 Ontology 的数据中心基础设施管理数据模型设计》教学大纲

## 一、课程基本信息

| 项目 | 内容 |
|---|---|
| 课程名称 | 基于 Ontology 的数据中心基础设施管理数据模型设计 |
| 英文名称 | Ontology-Driven Data Modeling for DCIM |
| 课程性质 | 架构设计与工程实践课程 |
| 建议学时 | 16～24 学时 |
| 建议课时 | 8～12 次课，每次 2 学时 |
| 适用对象 | DCIM 架构师、数字孪生工程师、数据库设计人员、BIM/ITSM/CMDB 集成人员 |
| 先修知识 | 数据库基础、数据中心基础设施基础、基本建模知识 |
| 教学方式 | 理论讲授、案例分析、建模练习、数据库实践、综合项目 |

---

## 二、课程定位

本课程面向数据中心基础设施管理、数字孪生和运维平台建设场景，讲解如何利用 Ontology 的理论和方法，对空间、资产、电力、制冷、网络、监控、业务依赖和运维对象进行统一建模，并进一步落实到关系数据库、RDF 知识图谱和时序数据库。

课程重点不是单独介绍某个标准，而是帮助学员掌握：

- 如何将多个行业标准统一到企业语义模型；
- 如何构建 DCIM Ontology；
- 如何使用 OWL、SHACL 和数据库约束；
- 如何将语义模型转换为可实施的数据库模型；
- 如何实现影响分析、数据质量和数字孪生关联。

---

## 三、教学目标

完成课程后，学员应能够：

1. 说明 DCIM 数据模型面临的主要问题。
2. 理解 ISO/IEC 22237、TIA-942、IFC、Redfish、BACnet、Brick、Haystack、SOSA/SSN、QUDT、PROV-O 等标准的角色。
3. 理解 Ontology、TBox、ABox、Class、Individual、Property 等基本概念。
4. 区分 Ontology、SHACL、关系数据库和时序数据库的职责。
5. 设计模块化的 DCIM Ontology。
6. 设计空间、资产、电力、制冷、网络和业务依赖模型。
7. 对复杂关系进行实体化。
8. 为动态关系加入有效时间和来源信息。
9. 编写基础的 SHACL 质量约束。
10. 设计可落地的 PostgreSQL 核心表结构。
11. 设计 Ontology 与数据库同步架构。
12. 使用能力问题验证模型完整性。
13. 实现基础的故障影响分析和合规检查。
14. 识别并避免常见 DCIM 数据建模误区。

## 七、教学方法

### 1. 概念讲授

用于讲解：

- Ontology 理论；
- 标准体系；
- 设计原则；
- 数据库分工。

### 2. 案例驱动

贯穿课程使用统一案例：

```text
机房
→ 机柜
→ 服务器
→ 双路供电
→ VM
→ 应用
→ 业务服务
```

### 3. 对比教学

重点对比：

- 树模型 vs 图模型；
- 传统数据库 vs Ontology；
- OWL vs SHACL；
- RDF vs PostgreSQL；
- IFC vs DCIM 主数据；
- 直接事实 vs 推理事实。

### 4. 实践教学

实践内容：

- Turtle；
- SHACL；
- SQL；
- 数据映射；
- 图查询；
- 数据质量检查。

### 5. 评审式教学

学员提交模型后，从以下角度评审：

- 是否能回答能力问题；
- 是否存在关系混用；
- 是否存在单一状态问题；
- 是否缺少时间和来源；
- 是否过度使用 JSONB；
- 是否错误使用传递关系。

## 十、推荐课堂案例

### 案例一：机柜 U 位冲突

问题：

- 两台设备在同一时间占用相同 U 位。

目标：

- 使用数据库排斥约束解决；
- 理解为什么仅使用 SHACL 不足以承担高并发事务约束。

### 案例二：双路供电不合规

问题：

- 服务器有两个 PSU，但都来自同一个 UPS。

目标：

- 使用关系实体化；
- 使用 SHACL-SPARQL 或规则引擎验证。

### 案例三：多来源位置冲突

问题：

- IFC 表示服务器在 Rack-A01；
- DCIM 表示服务器在 Rack-A02；
- Redfish 不包含位置。

目标：

- 保存多个断言；
- 应用权威来源矩阵；
- 生成冲突任务；
- 形成确认事实。

### 案例四：UPS 故障影响分析

问题：

- 查询 UPS-A 故障影响哪些业务。

目标：

- 跨电力、计算、虚拟化和业务领域查询；
- 区分确定依赖和潜在影响。

### 案例五：测点数据质量

问题：

- 部分测点缺少单位；
- 部分测点没有被测对象；
- 部分传感器的采集地址重复。

目标：

- 使用 SHACL 和数据库约束；
- 输出质量报告。

## 十二、课程总结要求

课程结束时，学员应形成以下完整认知：

```text
行业标准
    ↓
Ontology 统一语义
    ↓
SHACL 约束和规则
    ↓
Canonical Data Model
    ↓
PostgreSQL + RDF + TSDB
    ↓
数据接入、数字孪生、运维和影响分析
```

最终要求不是“建立一个概念模型”，而是建立一套能够：

- 被系统实施；
- 被数据验证；
- 被业务查询；
- 被持续治理；
- 被标准扩展；
- 被历史追溯；
- 被故障分析使用

的企业级 DCIM 数据模型体系。
